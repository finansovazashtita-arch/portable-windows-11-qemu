# Ръководство за подкарване на QEMU в Tails OS (от USB флашка)

Тъй като използвате **Tails OS** (която е "амнезична" операционна система, зареждаща се изцяло в RAM паметта) и стартирате от USB флашка, има няколко специфични ограничения, които пречат на QEMU да стартира нормално.

Ето основните причини, поради които командите не работят, и как да ги решите:

## 1. Липса на Администраторска парола (sudo)
По подразбиране Tails **не** ви дава администраторски права. За да инсталирате QEMU и да заредите KVM (хардуерното ускорение), трябва да сте задали парола при стартиране.
* **Решение:** При следващото рестартиране на компютъра, на екрана "Welcome to Tails", кликнете на **"+" (Additional Settings)**, изберете **Administration Password** и задайте парола.

## 2. QEMU не е инсталиран
Тъй като Tails не запазва инсталираните програми след рестарт (освен ако нямате Persistent Storage), QEMU най-вероятно липсва.
* **Решение:** Отворете терминал и изпълнете:
  ```bash
  sudo apt-get update
  sudo apt-get install -y qemu-system-x86 qemu-utils
  ```

## 3. Забрана за изпълнение (noexec) на USB флашката
Tails и други Linux дистрибуции често монтират външни флашки със защита `noexec`, което означава, че не можете да стартирате `.sh` скриптове директно с `./start_qemu_linux.sh`. Ще получите грешка "Permission denied".
* **Решение:** Стартирайте скрипта като изрично извикате bash:
  ```bash
  bash start_qemu_linux.sh
  ```

## 4. Проблем с KVM (Хардуерна виртуализация)
За да работи Windows 11 гладко, ви трябва хардуерно ускорение (KVM). Понякога в Tails модулите за KVM не са заредени или потребителят `amnesia` няма права до `/dev/kvm`. Освен това, уверете се, че в BIOS/UEFI на вашия Asus Vivobook 14 е включена виртуализацията (Intel VT-x или AMD-V).
* **Решение:** Заредете модулите и стартирайте с sudo:
  ```bash
  sudo modprobe kvm
  sudo modprobe kvm_intel  # Ако сте с Intel процесор
  # sudo modprobe kvm_amd  # Ако сте с AMD процесор
  
  # Стартирайте скрипта с администраторски права, за да има достъп до KVM
  sudo bash start_qemu_linux.sh
  ```

## 5. Недостатъчно RAM памет
Tails се зарежда изцяло в RAM паметта. Вашият скрипт `start_qemu_linux.sh` иска 4GB RAM (`-m 4096`). Ако вашият Asus Vivobook 14 има 8GB RAM, Tails може да няма достатъчно свободна памет (защото самата ОС заема част от нея) и QEMU ще "гръмне" веднага (Killed by OOM).
* **Решение:** Намалете паметта в скрипта на 3GB или 2GB (`-m 3072` или `-m 2048`), или затворете всички останали програми (като Tor Browser), докато пускате виртуалката.

## 6. Интернет достъп в Tails (Tor)
Tails блокира всякакъв мрежов трафик, който не минава през Tor. Виртуалната машина с Windows 11 няма да има достъп до интернет чрез стандартния `netdev user`.
Ако интернетът във виртуалната машина ви е важен, ще се наложи QEMU да бъде стартиран през `torsocks` (макар че Windows може да има проблеми с това) или да се ползва специална прокси конфигурация, но за офлайн употреба просто игнорирайте липсата на интернет.

---

### Специален скрипт за Tails
Създадох специален скрипт `start_qemu_tails.sh`, който автоматично се опитва да инсталира нужните пакети, зарежда KVM и решава проблемите с правата.
Можете да го стартирате така:
```bash
bash start_qemu_tails.sh
```
